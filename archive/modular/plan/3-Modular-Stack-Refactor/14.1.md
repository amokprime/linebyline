```
~/.local/bin/ruff -> ~/.local/share/uv/tools/ruff/bin/ruff
```

#### Why venv wins

Not size (identical — both pull the same 28 MB ruff binary). The deciding factor is **self-containment**, which I verified directly:

| | `pip install --target` | `python -m venv` |
|---|---|---|
| Console-script shebang | bare `#!/usr/bin/python3` | absolute `.../.lint-deps/bin/python3` |
| Package discovery | via ambient `PYTHONPATH`/`PYTHONHOME` | its own `site-packages` |
| Ambient `~/.local` interaction | can win over its own tree (host pygments **2.20.0** vs target **2.21.0**) | never sees it |
| Idempotency | re-copies every run | skip-if-present |
| Forensics | flat tree also holds real dirs (`ruff/`) | standard `pyvenv.cfg`, `lib/`, `bin/` |

Ruff survives `--target` only because it's a single native binary with no Python deps and no console script. Any *Python* tool added to `requirements-dev.txt` later (black, mypy, pre-commit) would resolve against ambient site-packages under `--target` — a silent, env-dependent break. That's the `find_ruff_bin` class of bug ([ruff #11246](https://github.com/astral-sh/ruff/issues/11246)), so venv is the mechanism that scales.

Tradeoff, stated honestly: venv imposes a `python3-venv`/`ensurepip` requirement (guarded with a clear error) and `PYTHONHOME` neutrality is a minor edge case. Given `--target`'s fragility, venv is the boring correct choice.
