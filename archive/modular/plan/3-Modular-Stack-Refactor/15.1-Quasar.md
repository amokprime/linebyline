#### Quasar (AI review)
1. **PR #11 is the modular stack refactor (Vite + Vue + TS + shadcn-vue)** — it's 43 commits, 52K+ additions, currently open and 95%+ complete (Phase E pre-cutover). Switching to Quasar now would throw away all of that work. Quasar is also Vue-based, so the component code could in principle be ported — but Quasar has its own component library (120+ components) that would replace shadcn-vue, requiring a full UI rewrite.

2. **MAYBE.md's Desktop app proposal explicitly considered Quasar-like frameworks and rejected them** — the user's notes say: "Potentially learning and maintaining a different desktop architecture. Any UI design substantially outside of established web frameworks with off-the-shelf themes and icons would probably involve iterating with a powerful local or API model with computer use. I use the free chat.z.ai sandbox which has no GPU (besides Linux Wayland computer use is terrible)." Quasar would require Electron (desktop) which is a different testing/CI surface (Playwright works on Electron, but the build/deploy pipeline changes).

3. **MAYBE.md's PWA proposal is the lightweight path** — LineByLine already has a GitHub Pages site (the monolith) + a Vite SPA (post-PR #11). PWA is a manifest.json + service worker — no framework change needed. Quasar's PWA mode adds nothing the Vite PWA plugin doesn't already provide.

4. **The "write once, deploy everywhere" value prop is weak for LineByLine's use case** — the app is a lyrics syncing tool used on PC (the user: "I don't listen to music on my phone"). Mobile + desktop targets are explicitly deprioritized in MAYBE.md. Quasar's main value (cross-platform) is value the user doesn't need.

5. **Electron specifically has testing concerns** — MAYBE.md notes "It would also need a solid testing framework like Playwright that works on Wayland Linux so I can run tests locally." Playwright DOES support Electron, but the test setup changes (main process vs renderer process, IPC mocking, etc.). The current Playwright suite (354 tests) targets the web build; an Electron port would need a parallel suite.

6. **The current path is closer to cutover than to a rewrite** — Tranche 5 (Pages source flip) is the next major milestone. After cutover, the live site runs the Vite build. PWA support can be added as a Tranche 6+ enhancement. Desktop (Electron) can be revisited post-cutover if the user's needs change — and at that point, the question is "do we add Electron to the existing Vite app?" (vite-plugin-electron) rather than "do we rewrite in Quasar?".

**Recommendation**: stay the course with Vite + Vue + shadcn-vue. Post-cutover, if the user wants a desktop app, the cheapest path is `vite-plugin-electron` (adds Electron to the existing Vite build — no framework switch, no UI rewrite). Quasar would be a full rewrite for cross-platform value the user has explicitly deprioritized. If mobile becomes a real need later, Capacitor can be added to the Vite app (again, no framework switch).

**When to reconsider**: if the user's "Desktop app" MAYBE proposal becomes a real priority AND they want to drop the GitHub Pages site entirely (the MAYBE.md note: "if I could get desktop + PWA unified and working, I'd probably just drop the GitHub Page"), then a framework switch is more justifiable — but even then, `vite-plugin-electron` + `vite-plugin-pwa` covers the same ground without Quasar.
