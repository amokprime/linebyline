## Assessment per finding (per sonarqube-workflow-SKILL.md Step 3)

**L23 S6505 — `npm ci` missing `--ignore-scripts`.** Fix. Adding `--ignore-scripts` prevents any dependency's `postinstall`/`prepare`/`preinstall` scripts from executing arbitrary code during install. Safe in this project because `@playwright/test`'s browser download (the only postinstall that matters) is explicitly handled by the next step (`playwright install --with-deps`). Audited `package.json` deps — none of `@eslint/js`, `eslint-plugin-sonarjs`, `serve`, `@axe-core/playwright`, `@types/node`, `eslint`, `globals` need lifecycle scripts to function. The local file dep `@linebyline/test-helpers` has no `prepare`/`postinstall` of concern.

**L26 + L29 S6505 — `npx playwright …` flagged for on-demand install risk.** Fix. `npx` is flagged because it can install a package on-demand if not found in `node_modules`. After `npm ci`, the `playwright` binary IS in `node_modules/.bin/`. Replacing `npx playwright` with `./node_modules/.bin/playwright` runs the locally-installed binary directly — no on-demand install path exists, eliminating the vulnerability.

**L26 + L29 S8543 — pin exact package version.** Fix, resolved by the same change as S6505. `./node_modules/.bin/playwright` runs the version pinned in `package.json` (`@playwright/test: ^1.61.0`). No on-demand install means no risk of pulling an unverified release.

**Won't Fix decisions: none.** All 5 findings are real vulnerabilities with straightforward fixes. No false positives in this batch.

## Workers bump — feasibility assessment (Propose, not patched)

The CI output shows `Running 540 tests using 1 worker`. Playwright defaults to 1 worker when `CI=true` is set; locally it defaults to `os.cpus()/2` — that's why your laptop gets 4 (8 cores / 2). Bumping is feasible but capped by the runner.

**GitHub `ubuntu-latest` runner specs:** 4 vCPUs, 16 GB RAM. Each Playwright worker spawns its own browser process (~300-500 MB RAM, significant CPU). With the Firefox flakiness already noted in `archive/modular/plan/0-Roadmap.md` ("All three browsers run in CI per preference; Firefox is the flakiest"), worker count trades speed for flakiness risk:

| Workers | Estimated speedup | Contention risk | Recommendation |
|---|---|---|---|
| 1 (current) | baseline | none | Safe baseline |
| 2 | ~40-50% | low | **Recommended starting point** |
| 3 | ~55-65% | moderate | Acceptable |
| 4 | ~65-75% theoretical | high — saturates 4-vCPU runner, amplifies Firefox flakiness | Not recommended |

**Where to set it:** in the workflow command, not in `playwright.config.js`. CLI override is CI-only and leaves local dev behavior unchanged:

```yaml
- name: Run Playwright tests
  run: ./node_modules/.bin/playwright test --workers=2
```

If you want to try the bump, edit `playwright-v2.yml` line 29 to add `--workers=2` (or `--workers=3`), push, and watch the next CI run for new flaky failures (especially Firefox). If green for ~5 pushes, consider bumping one more notch. If Firefox flakes appear, drop back.

The patched `playwright-v2.yml` as delivered does NOT include the workers bump — I kept the Sonar fix and the workers proposal as separate concerns so you can decide on workers independently.
