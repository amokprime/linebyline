## Path 1: are the headless errors latent cross-platform bugs?

Partially yes — and the failure notes you kept already let us classify each one. Three buckets:

**Real bugs that would fail on every platform, headed or headless:**

- `TypeError: Cannot read properties of undefined (reading 'raw')` in `fields-merge.spec.js` — this is the aria-snapshot YAML parser choking on unquoted text values that *start with `(`` (we traced this last session). It will crash identically on Windows, Fedora, Ubuntu, headed, headless, every Playwright version that ships that tokenizer. `--ui` did NOT actually pass these — they were never green, you just hadn't run them.
- `split-paren` (firefox) — `expected: ""` vs. `received: 17 lines` means the snapshot file `split-paren-lines-firefox-linux.txt` exists but is empty. That's a bad baseline file committed to the repo, not a rendering or timing issue.
- `font` PNG diff (2 px chromium / 390 px firefox) — pure font-rendering drift between whatever system the baseline was generated on and your current machine. Same drift will exist on GitHub runners if their font stack differs from yours.

**Timing/race issues that `--ui` masks because `--ui` is slower:**

- `intervals/speed-ratio` — got `0.91` instead of `0.67`. That's the keyboard shortcut (`Control+2`?) firing before the previous speed-adjust handler settled. `--ui` runs slower so the race doesn't trigger.
- `intervals/typing-debounce-1` — same family. The `Control+z` undo fires before the debounce flushes the textarea value.
- `merge-line-mismatch` toast — toast *does* appear in real Helium (you screenshotted it). Headless Chromium either dismisses it faster than the 5s `expect` polls, or `Control+6` isn't being delivered the same way. Real app behavior is fine; the test needs `expect.poll` or a longer timeout, not a code change.

**Cross-platform pixel drift (would surface on CI too, but is genuinely environmental):**

- `replay-sync-time` screenshot — same family as `font`. Font rasterization differs between your baseline system and your current one.

So the framing isn't "headless errors are latent bugs" vs. "headless errors are environmental." It's:
- ~50% are real bugs you'd hit anywhere → fix the test/snapshot, full stop
- ~30% are timing races that headless mode surfaces because it's faster → add waits or use `expect.poll`
- ~20% are pixel/font drift → regenerate baselines on a stable environment, or pin a web font

`--ui` is **not** a reliable "truth" baseline here. It's a debugging tool that happens to mask timing races because it runs slow. CI will hit the same races.

## Path 2: containerized Ubuntu runner — yes, do this

It's a good idea, but not for the reason you might think. It won't fix the TypeError (Playwright bug, OS-independent) or the timing races (inherent to headless). What it *will* fix:

1. **Snapshot reproducibility.** If the container's Ubuntu image matches GitHub's `ubuntu-latest` (currently 24.04 noble), PNG baselines you generate locally will match what CI generates. No more `font-hotkey` 2px drift surprise on push.
2. **WebKit stops being flaky.** WebKit on Fedora was "officially unsupported, falls back to Ubuntu build, missing libs." WebKit on Ubuntu container is first-class. You can re-enable the `webkit` project locally and trust the results.
3. **Isolation from KDE/Wayland/fontconfig interference.** No more "did Plasma intercept Control+6" investigation; no more Cantarell-vs-Ubuntu font drift.
4. **`install-deps` actually works.** Inside Ubuntu it runs `apt-get` like Playwright expects.

### Podman vs. Distrobox vs. Docker on Fedora

| Tool | Fit for "mirror CI exactly" | Fit for "visible window in Fedora" |
|---|---|---|
| **Podman** (preinstalled) | ✅ Best — clean isolated env, no home dir bleed | ✅ Works via X11/Wayland socket passthrough |
| **Distrobox** | ❌ Undermines the goal — mounts your home dir, fonts, dotfiles. You'd be back to Fedora's font stack influencing rendering | ✅ Best — GUI apps appear as native windows |
| **Docker** | ✅ Same as Podman | ✅ Same as Podman |
| | Skip on Fedora — redundant with Podman, needs daemon/sudo/group | |

**Recommendation: Podman.** Distrobox is the wrong tool for this specific goal — it's designed to make Ubuntu feel native on Fedora, which is the opposite of "reproduce CI exactly." Distrobox would share your `~/.fonts`, your `~/.config/fontconfig/`, your KDE theme — exactly the drift sources you're trying to eliminate.

### Concrete setup

Use Microsoft's official Playwright image, which is Ubuntu 24.04 with all browser deps preinstalled:

```fish
# One-time: pull the image matching your installed Playwright version
podman pull mcr.microsoft.com/playwright:v1.61.0-noble
```

For **headless** runs (the CI-mirror case):

```fish
podman run --rm -it \
  --userns=keep-id \
  -v $PWD:/home/pwuser/repo:z \
  -w /home/pwuser/repo \
  -e CI=1 \
  mcr.microsoft.com/playwright:v1.61.0-noble \
  npx playwright test
```

The `:z` suffix on the volume mount is needed on Fedora because SELinux would otherwise deny the container access to your repo files. `--userns=keep-id` maps your UID so files written by the container (snapshots, trash/) are owned by you on the host.

For **`--ui` mode with a visible window in Fedora** (Plasma 6 on Wayland):

```fish
# Allow the container's UID to talk to your Wayland socket
xhost +SI:localuser:$(whoami)

podman run --rm -it \
  --userns=keep-id \
  --security-opt label=disable \
  --net=host \
  -e DISPLAY=$DISPLAY \
  -e WAYLAND_DISPLAY=$WAYLAND_DISPLAY \
  -e XDG_RUNTIME_DIR=/tmp \
  -v $XDG_RUNTIME_DIR/$WAYLAND_DISPLAY:/tmp/$WAYLAND_DISPLAY:z \
  -v $XDG_RUNTIME_DIR/pipewire-0:/tmp/pipewire-0:z \
  -v $PWD:/home/pwuser/repo:z \
  -w /home/pwuser/repo \
  --ipc=host \
  mcr.microsoft.com/playwright:v1.61.0-noble \
  npx playwright test --ui
```

`--net=host` lets the container's port 9323 (UI mode web server) show up in your Fedora browser without port mapping. `--ipc=host` is needed for Chromium's shared memory on some setups. If Wayland forwarding is flaky, fall back to X11: drop the Wayland env/vars and add `-v /tmp/.X11-unix:/tmp/.X11-unix:z` instead.

For a quicker day-to-day workflow, wrap these in fish functions:

```fish
function tstc  # "test container"
    podman run --rm -it --userns=keep-id \
        -v $PWD:/home/pwuser/repo:z -w /home/pwuser/repo \
        -e CI=1 mcr.microsoft.com/playwright:v1.61.0-noble \
        npx playwright test $argv
end

function tstac  # "test UI container"
    podman run --rm -it --userns=keep-id --security-opt label=disable \
        --net=host --ipc=host \
        -e DISPLAY=$DISPLAY -e WAYLAND_DISPLAY=$WAYLAND_DISPLAY \

        npx playwright test --ui $argv
end
funcsave tstc
funcsave tstac
```

## Root cause

The bind-mount target path is the bug. I had you mount to `/home/pwuser/repo`, which traverses `/home/pwuser/`. Inside the MS Playwright image, `/home/pwuser/` is owned by `pwuser` (uid 1000) with typical home-dir permissions (mode 700 or 750 — owner-only traverse). When `--userns=keep-id` maps your host UID into the container, two scenarios:

1. **If your host UID is 1000** → you map to uid 1000 inside, which IS `pwuser`, traverse works. (Your output suggests this isn't the case — the error log path was `/home/ubuntu/.npm/_logs/`, hinting the image's actual default user is `ubuntu`, not `pwuser`.)
2. **If your host UID is anything else** (e.g. 1001) → you map to that UID inside, which is NOT `pwuser`, and `/home/pwuser/` is unreachable. The bind mount at `/home/pwuser/repo` exists but you can't `cd` into it because the parent directory denies you traverse. Hence `spawn sh EACCES` — Node can't spawn a child whose `cwd` is unreachable.

Either way, the fix is the same: don't bind-mount through anyone's home directory.

## 1. You ran the sanity check from `~`, not from the repo

Look at the prompt: `user@PC ~>` means `$PWD = /home/user`. There's no `node_modules/` in your home directory anyway, so even if the SELinux error didn't fire, the test would have failed differently. I should have told you to `cd` first.

But more importantly:

## 2. The `:z` suffix is the problem, not the solution

The `:z` (lowercase) on a Podman volume mount tells SELinux to **persistently relabel** the host files so the container can read them. Podman explicitly refuses to do this for protected paths like `/home/user`, `/tmp`, `/etc` — that's the error you hit. It would persistently relabel `~/GitHub/linebyline` too (which works, but it's an unnecessary side-effect that lingers on your host filesystem forever).

The cleaner alternative you're asking for: **drop `:z` entirely and use `--security-opt label=disable`**. This disables SELinux confinement for the container process — it can then read any file you bind-mount without any relabeling. The host files stay untouched. This is already what `tsta` does; `tst` just needs the same treatment.

Bonus: your host UID is 1000, and the MS Playwright image's default user (`ubuntu`) is also uid 1000. So `--userns=keep-id` is effectively a no-op identity mapping — files just work natively.
