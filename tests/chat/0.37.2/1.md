## Root cause analysis per category

**1. Clipboard race (8 tests affected)** — `navigator.clipboard.writeText()` is async. Even though `page.evaluate()` awaits the Promise, the clipboard may not be populated when `Control+v` fires immediately after. On fast CI runners (1 worker, no contention), the race window is tight — sometimes the paste reads an empty clipboard, producing an empty textarea. The 4 flaky tests passed on retry (2 retries configured); `paste-secondary` failed all 3 attempts because the ambiguous selector compounded the race.

Fix: add `await page.waitForTimeout(50)` between the `evaluate` that writes to clipboard and the `Control+v` press. 50ms is enough for the clipboard API to settle without slowing the suite meaningfully (8 paste tests x 50ms = 0.4s total).

**2. Ambiguous selector in `paste-secondary` and `paste-secondary-genius`** — Both tests do `await page.getByRole("textbox").click()` after `Control+4` (add secondary field). After `Control+4`, there are 2 textareas on the page: `#main-textarea` and `.sec-textarea`. `getByRole("textbox")` matches both — Playwright's strict mode should throw, but if it resolves to the first match (main textarea), the paste goes to the wrong element.

Fix: replace `getByRole("textbox")` with `getByLabel("Secondary 1 lyrics")` — the secondary textarea has `aria-label="Secondary 1 lyrics"` (confirmed by `hide-secondary` and `replace-secondary` tests which use this label).

**3. `typing-debounce-1`** — The test sets the undo window to 1ms, then types `a`, `b`, `c` in rapid succession. With Playwright's sub-millisecond keypress timing, all three letters land within the 1ms debounce window and merge into a single undo snapshot. The test then presses `Control+z` twice, expecting to undo `c` then `b` (leaving `a`). But since all three are in one snapshot, the first undo removes `abc` entirely and the second undo does nothing — leaving an empty textarea.

The `playwright-testing-SKILL.md` documents this exact issue: "1ms debounce + Playwright's <1ms keypresses → all letters land in one snapshot. Add `waitForTimeout(5)` between keypresses so the debounce fires separately for each."

Fix: add `await page.waitForTimeout(5)` between each keypress (`a`→`b`→`c`) and before the undo loop, so each letter gets its own undo snapshot.

**4. Font-fragile screenshots (9 failures across 3 tests x 3 browsers)** — `tab-font`, `audio-missing-noop`, and `assign-reserved-click` all use `toHaveScreenshot()` on elements whose dimensions depend on text rendering. The baselines were generated in the `tst` Podman container (ubuntu-24.04), but CI runs on `ubuntu-latest` — a different Ubuntu image with different system-ui font metrics.

The `playwright-testing-SKILL.md` says these tests should "skip in UI mode on host; still runs in CI and `tst` container where the baseline was generated." The assumption was that `tst` container == `ubuntu-latest` for font rendering. The CI failures prove this assumption is wrong: ubuntu-latest renders `system-ui` slightly wider than the Podman container, causing `#main-textarea` to be 954px instead of 970px, `#audio-box` to be 181px instead of 190px, and `.hk-row` to be 82px instead of 87px.

The `maxDiffPixelRatio: 0.05` (5%) tolerance in `playwright.config.js` doesn't help because Playwright rejects screenshots with different dimensions before applying the pixel ratio.

Fix: replace `toHaveScreenshot()` with structural assertions that don't depend on font rendering:
- `tab-font`: already checks `#font-select` value is "serif". Replace screenshot with `toHaveCSS("font-family", "serif")` on `#main-textarea`. Remove the `test.skip(!CI && !PW_CONTAINER)` guard — structural assertions don't need it.
- `audio-missing-noop`: replace 3 screenshots with `toBeVisible()` on "Unknown Title" / "Unknown Artist" text, `toHaveText("0:00")` on `#time-pos` / `#time-dur`, and `toBeVisible()` on "audio" after import.
- `assign-reserved-click`: replace screenshot with `toHaveValue("Ctrl+;")` on the reset hotkey field (the default for toggle_mode after reset).

**5. Missing snapshot baselines (5 failures)** — `paste-secondary-genius` (chromium+firefox), `paste-genius-hotkey` (chromium+firefox), `paste-genius-typing` (chromium+firefox) all fail with "A snapshot doesn't exist... writing actual." These are new tests added without committed baselines. Playwright writes the actual output but fails the assertion because there's nothing to compare against.

The clipboard race fix and selector fix address the root causes that might produce wrong output. My `settings-v1.spec.js` replaced the original `toHaveScreenshot()` (on the whole hotkeys panel) with `toHaveValue("Ctrl+;")` on the `offset_mode_toggle` capture field. I incorrectly assumed `Ctrl+;` was the default for `offset_mode_toggle`.

### Root cause 2: `search-check` — webkit Tab fragility after search filter (1 browser)

The CI diff shows all 3 letters (`a`, `b`, `c`) were in ONE undo snapshot despite my Turn 3 `waitForTimeout(5)` between keypresses. After 2x `Control+z`, the textarea was empty (expected: just `a` after the metadata). The test passed on retry (marked `±` flaky), but flaky tests are unreliable.

**Why 5ms isn't enough on CI:**

The undo system uses a 1ms debounce to group rapid keypresses into one snapshot. My v1 added `waitForTimeout(5)` between keypresses — 5x the debounce window. Locally this is sufficient. On CI, the browser event loop is under contention (1 worker, 540 tests, shared runner), and the 1ms debounce timer may not fire within the 5ms window. Possible causes:
- The undo system may use `requestAnimationFrame` (16ms interval) rather than `setTimeout(1ms)` for snapshot finalization
- V8's `Date.now()` may have coarser resolution on the CI runner, causing the debounce's time comparison to see all 3 keypresses as "simultaneous"
- Playwright's `waitForTimeout(5)` is a Node-side wait; under event-loop pressure, the browser process may not process the debounce timer within 5ms of wall-clock time

**Fix:** bump `waitForTimeout(5)` → `waitForTimeout(20)`. 20ms is well above:
- The ~16ms `requestAnimationFrame` interval (60fps)
- The ~10ms clock-tick resolution on older kernels
- Any reasonable event-loop scheduling jitter

3 keypresses × 20ms = 60ms total — still negligible in a 5.4m suite.

## Fix: negation pattern in `.gitignore`

Delivered as `gitignore-v1` (in `download/`). One line added immediately after `*genius*`:

```
*genius*
# Genius paste snapshot baselines must be tracked (un-ignored from *genius* above)
!tests/*.spec.js-snapshots/*genius*.txt
```

Git's negation rules allow re-including a file if the file itself was ignored (not its parent directory). Here `*genius*` matches the `.txt` files directly — their parent directories (`tests/`, `tests/*.spec.js-snapshots/`) don't contain "genius" and aren't ignored. So the negation works.

The negation is narrow: it only un-ignores `.txt` files in `tests/*.spec.js-snapshots/` directories that contain "genius" in the filename. Any other `*genius*` files (local notes, `.md` files, `.json` mocks, etc.) stay ignored as before.
