## About

This file explains how I setup ZCode during the GLM-5.3-Flash promotion period and used it to work on LineByLine. WIP.

### Setup
1. Login to chat.z.ai and connect ZCode to your account
2. Download the AppImage to some persistent folder (i.e `~/.zcode/executable/*.AppImage`), double-click it and approve execution. The desktop entry created is based on the original executable path. So if you naively downloaded the AppImage to `~/Downloads` and deleted it, restore it and edit the menu entry path to a persistent path.
3. Sign in via chat.z.ai (no need for API key) and claim the GLM-5.3-Flash promotion
4. Skills can be added with Settings -> Onboard or project-scoped in `.zcode/skills/`. You might need to restart ZCode to load them.

### Usage
1. Sometimes the agent gets cutoff with an error like below. Probably the equivalent of the web UI captcha popup but invisible. Send a "." message to get the agent to continue.
```
ZCode Error Info

Error Summary
Model request failed.

TraceID: blahblah

Error Details
Turn execution failed
provider=builtin:zai-start-plan model=GLM-5.3-Flash request=blahblah reason=unknown retryable=false
Captcha instance timed out after 10000ms.
```
2. An Undo button appears after the agent works on code artifacts.

### Transcript export

`transcript.sh` distills a session's raw rollout log (`~/.zcode/cli/rollout/model-io-sess_<uuid>.jsonl` — one JSON line per model call, never commit raw) into the Obsidian-friendly transcript format used for the `archive/` companions. User and agent prose per turn, verbatim; tool calls, thinking blocks, GLM server-tool narration, and harness-injected `<system-reminder>` blocks dropped; in-content headers demoted so they never collide with the turn/label hierarchy; a user turn that is only a continue-phrase ("Continue", ".") is dropped and its agent output merged into the interrupted turn. Reminder-wrapped file attachments ("Contents of <path>") are kept as `**filename:**` blocks when small, filename-only when large or images.

```sh
ai/zcode/transcript.sh                            # dest from clipboard (see below), else newest session → stdout
ai/zcode/transcript.sh sess_a0313926              # by id or unique id prefix → stdout
ai/zcode/transcript.sh -o /tmp/t.md sess_a0313926 # explicit output file
ai/zcode/transcript.sh -d archive/modular/0.37.2  # destination folder, autogenerated filename
ai/zcode/transcript.sh --help                     # short usage; -o --help / -d --help for flag details
```

Destination filename autogenerates from the folder: `X.XX.XX.md` when the folder name is semver (the `archive/semantic|modular/X.XX.XX` profile), otherwise the next free `1.md`, `2.md`, … beyond existing numbered files. A destination-generated file that already exists is refused (`-o` still overwrites deliberately). With `-d`, relative paths resolve against the repo root, and the leaf folder is created if its parent exists.

With **no arguments** (copy a path, then double-click the script in Dolphin), the destination folder comes from the clipboard via `wl-paste` — primary selection first, then clipboard, whitespace/unquote/`file://`-stripped like `~/.bash/quote-gif.sh`; absolute or repo-relative paths both work, and an existing `.md` file on the clipboard means "write next to it". The clipboard path must already exist — nothing is ever created from clipboard content. If no usable path is found the script falls back to newest session → stdout, and `notify-send` pings when a file is written.

Frontmatter presets (`MODEL`, `PROVIDER`, `HARNESS`), the rollout directory (`ROLLOUT_DIR`), and the attachment size cutoff (`ATTACH_MAX_CHARS`) are variables at the top of the script, overridable via environment.
