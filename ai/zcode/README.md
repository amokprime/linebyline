## About

This file explains how I setup ZCode during the GLM-5.3-Flash promotion period and used it to work on LineByLine. WIP.

### Setup
1. Login to chat.z.ai and connect ZCode to your account
2. Download the AppImage to some persistent folder (i.e `~/.zcode/executable/*.AppImage`), double-click it and approve execution. The desktop entry created is based on the original executable path. So if you naively downloaded the AppImage to `~/Downloads` and deleted it, restore it and edit the menu entry path to a persistent path.
3. Sign in via chat.z.ai (no need for API key) and claim the GLM-5.3-Flash promotion
4. Skills can be added with Settings -> Onboard or project-scoped in `.zcode/skills/`. You might need to restart ZCode to load them.

### Usage
1. Sometimes the agent gets cutoff with an error like below. Probably the equivalent of the web UI captcha popup but invisible. Send a "." message to get the agent to continue.
```
ZCode Error Info

Error Summary
Model request failed.

TraceID: blahblah

Error Details
Turn execution failed
provider=builtin:zai-start-plan model=GLM-5.3-Flash request=blahblah reason=unknown retryable=false
Captcha instance timed out after 10000ms.
```
2. An Undo button appears after the agent works on code artifacts.

### Transcript export

`transcript.sh` distills a session's raw rollout log (`~/.zcode/cli/rollout/model-io-sess_<uuid>.jsonl` — one JSON line per model call, never commit raw) into the Obsidian-friendly transcript format used for the `archive/` companions. User and agent prose per turn, verbatim; tool calls, thinking blocks, GLM server-tool narration, harness-injected `<system-reminder>` blocks, and bare `<task-notification>` blocks dropped (the latter so background-task notices can't be mistaken for steering); in-content headers demoted so they never collide with the turn/label hierarchy; a user turn that is only a continue-phrase ("Continue", ".") is dropped and its agent output merged into the interrupted turn; the auto-compaction context summary injected as a user message after a context break ("This session is being continued from a previous conversation…") is excluded entirely — it duplicates the turns already in the log, and its quoted marker syntax would otherwise false-match the attachment extractor. Reminder-wrapped file attachments ("Contents of <path>") are kept as `**filename:**` blocks when small, filename-only when large or images. User messages steered in mid-turn (same turn ID, arriving in later model calls of the turn) are kept: each renders as a `> **Steering:**` blockquote under the originating prompt, in the order it was sent. Side-conversation rollouts are refused before any output is written — side conversations are deliberately temporary by design (docs: zcode.z.ai/en/docs/agents#side-conversation), so they're out of scope for exports; the refusal is role-aware (the injected inherited-context banner must be a user message), so a main-session log that merely quotes the banner in tool output still exports. Attachments collapse into a `**Attachments:**` list of backticked filenames after the message — typed image/file parts, `[Image: source: …]` text markers (stripped from the prose; the private cache path is never kept), pasted base64 data URIs, and reminder-wrapped attachments that are images or above the size cutoff — deduplicated. Reminder-wrapped small text files keep their content inline as `**filename:**` blocks. The harness prunes rollout logs in place mid-session, so a log can lose turns it once held; when a fresh export has fewer turns than the transcript file it overwrites, the script prints a stderr warning (pruned-log signature — earlier turns then survive only in git history and the live conversation).

```sh
ai/zcode/transcript.sh                            # dest from clipboard (see below), else newest session → stdout
ai/zcode/transcript.sh sess_a0313926              # by id or unique id prefix → stdout
ai/zcode/transcript.sh /tmp/t.md sess_a0313926    # explicit output file (overwrites by default)
ai/zcode/transcript.sh archive/semantic/0.37.2/refactor.md sess_a0313926  # update a transcript in place
ai/zcode/transcript.sh archive/modular/0.37.2     # destination folder, autogenerated filename
ai/zcode/transcript.sh --help                     # full usage
```

Arguments are recognized by what they are, so `[PATH] [SESSION]` is self-evident and either order works: a session id or `.jsonl` path is a source, a directory or `.md` file is a destination. An existing directory gets an autogenerated filename — `X.XX.XX.md` when the folder name is semver (the `archive/semantic|modular/X.XX.XX` profile), otherwise the next free `1.md`, `2.md`, … beyond existing numbered files (numbering counts only existing `N.md` files, jumping past gaps, so numbered names never collide). An existing `.md` file is overwritten — same-path reruns update the transcript in place; a new `*.md` path is created when its parent exists; a new extensionless path containing a slash is created as a directory. Relative paths resolve against the repo root first, then the current directory. `--no-clobber`/`-nc` refuses to overwrite an existing output file instead.

With **no arguments** (copy a path, then double-click the script in Dolphin), the destination comes from the clipboard via `wl-paste` — primary selection first, then clipboard, whitespace/unquote/`file://`-stripped like `~/.bash/quote-gif.sh`. The copied path must already exist — nothing is ever created from clipboard content: a copied folder gets an autogenerated transcript, a copied `.md` file is overwritten in place. If no usable path is found the script falls back to newest session → stdout, and `notify-send` pings when a file is written.

Frontmatter presets (`MODEL`, `PROVIDER`, `HARNESS`), the rollout directory (`ROLLOUT_DIR`), and the attachment size cutoff (`ATTACH_MAX_CHARS`) are variables at the top of the script, overridable via environment.
